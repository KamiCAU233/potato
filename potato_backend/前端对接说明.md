# 马铃薯病害识别 - 前端对接说明

本文档提供给前端同学：如何运行后端、如何调用接口。

---

## 一、如何运行后端（本地联调时）

### 1. 获取运行包

从后端同学处获取 **potato_backend_package.zip**，解压到任意目录（解压后应看到 `backend` 文件夹、`data` 文件夹（含 scaler 文件）与 `backend_package_README.txt` 等同级）。

> **重要**：`data/scalers/scaler.pkl` 是时序预测的必要文件，已预生成包含在包中。

### 2. 安装依赖

在**解压后的根目录**（与 `backend` 同级）打开终端，执行：

```bash
pip install -r backend/requirements.txt
```

### 3. 启动服务

在同一目录下执行：

```bash
uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```

看到 `Uvicorn running on http://0.0.0.0:8000` 即启动成功。

### 4. 验证

浏览器访问：**http://127.0.0.1:8000/docs**，可在此页面上传图片、测试问答等接口。

### 5. 可选：启用大模型（问答、识别+解读）

若需要「病害问答」和「识别结果解读」功能，在解压后的**根目录**新建 **.env** 文件，内容示例：

```
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=你的DeepSeek的key
LLM_MODEL=deepseek-chat
```

不配置也可运行，此时识别接口正常，问答与解读接口会返回「大模型未启用」。

### 6. 可选：启用扣子智能体（问答功能）

若需要「扣子智能体问答」功能，在解压后的**根目录**新建或编辑 **.env** 文件，添加：

```
ENABLE_COZE=true
COZE_BOT_ID=你的机器人ID
COZE_PAT=你的个人访问令牌
```

不配置也可运行，此时扣子智能体问答接口会返回「扣子智能体未启用」。

## 二、接口说明（前端调用）

**Base URL**：本地联调 `http://127.0.0.1:8000`，部署后改为实际服务器地址。

### 1. 上传图片识别（只返回最可能的 1 条病害）

- **URL**：`POST /api/predict`
- **Content-Type**：`multipart/form-data`
- **请求**：表单字段名 **file**，值为图片文件（jpg/png/bmp 等）
- **响应示例**：
```json
{
  "success": true,
  "results": [
    {
      "class": "叶片晚疫病",
      "confidence": 0.8523,
      "box": [100.5, 80.2, 300.1, 250.8]
    }
  ],
  "image_result": "base64编码的带框结果图，可直接用于img src展示",
  "monthly_tip": "当前为X月，易发XXX，请多关注..."
}
```
- **说明**：`results` 最多 1 条，为置信度最高的病害；无检测到时为 `[]`。

### 2. 病害问答（支持多轮）

- **URL**：`POST /api/ask`
- **Content-Type**：`application/json`
- **请求体**：
```json
{
  "question": "晚疫病怎么防治？",
  "history": [
    { "role": "user", "content": "晚疫病是什么？" },
    { "role": "assistant", "content": "晚疫病是..." }
  ]
}
```
- **说明**：`history` 可选，不传或传 `[]` 为单轮；传则实现多轮对话，建议只保留最近几轮。
- **响应示例**：
```json
{
  "success": true,
  "answer": "大模型返回的回答文本",
  "message": null
}
```
- 失败或大模型未启用时：`success: false`，`answer: null`，`message` 为错误或说明。

### 3. 上传图片识别并生成解读

- **URL**：`POST /api/predict_with_explanation`
- **Content-Type**：`multipart/form-data`
- **请求**：同 `/api/predict`，表单字段 **file** 为图片。
- **响应示例**：
```json
{
  "success": true,
  "results": [{ "class": "叶片晚疫病", "confidence": 0.85, "box": [...] }],
  "image_result": "base64...",
  "explanation": "大模型根据检测结果生成的解读与防治建议",
  "message": null,
  "monthly_tip": "当前月份易发病提示..."
}
```
- 大模型未启用时：`explanation` 为 `null`，`message` 为「大模型未启用」类说明。

### 4. 当前月份易发病提示

- **URL**：`GET /api/monthly_tip`
- **响应示例**：
```json
{
  "monthly_tip": "当前为X月，易发晚疫病、早疫病，请多关注叶片与块茎。"
}
```

### 6. 扣子智能体状态（调试用）

- **URL**：`GET /api/coze_status`
- **响应示例**：
```json
{
  "coze_available": true,
  "enable_coze": true,
  "has_bot_id": true,
  "has_pat": true
}
```

### 7. 扣子智能体问答（支持多轮）

- **URL**：`POST /api/coze/ask`
- **Content-Type**：`application/json`
- **请求体**：
```json
{
  "question": "晚疫病怎么防治？",
  "history": [
    { "role": "user", "content": "晚疫病是什么？" },
    { "role": "assistant", "content": "晚疫病是..." }
  ]
}
```
- **说明**：`history` 可选，不传或传 `[]` 为单轮；传则实现多轮对话，建议只保留最近几轮。
- **响应示例**：
```json
{
  "success": true,
  "answer": "扣子智能体返回的回答文本",
  "message": null
}
```
- 失败或扣子智能体未启用时：`success: false`，`answer: null`，`message` 为错误或说明。

### 8. 地名转经纬度（地理编码）

- **URL**：`GET /api/geocode?name=地名`
- **说明**：调用 Open-Meteo 的地名解析接口，将地名转换为经纬度、时区等信息。
- **响应示例**：
```json
{
  "success": true,
  "result": {
    "name": "北京市",
    "latitude": 39.9042,
    "longitude": 116.4074,
    "country": "中国",
    "timezone": "Asia/Shanghai"
  }
}
```
- **错误示例**（未找到地名）：
```json
{
  "detail": "未找到地名: XXX"
}
```

### 9. 按经纬度进行时序预测（推荐用法）

- **URL**：`POST /api/time_series_predict_by_location`
- **Content-Type**：`application/json`
- **请求体**：
```json
{
  "latitude": 39.9042,
  "longitude": 116.4074
}
```
- **说明**：
  - 自动调用 Open-Meteo 天气 API 获取气象数据，并计算 6 维特征
  - 整合时序模型进行预测，输出当天发病风险概率
  - 概率 > 0.6 表示高风险（训练时使用的业务阈值），< 0.6 表示低风险
- **响应示例**：
```json
{
  "success": true,
  "prediction": 0.6523,
  "input": [22.3, 25.0, 18.1, 12.0, 4.5, 48.0],
  "message": "按经纬度预测成功"
}
```
- **说明**：
  - `prediction`：预测概率（0～1），越接近 1 表示越容易发病
  - `input`：用于预测的 6 维特征（可用于调试），包含：
    1. avg_temp_7d
    2. max_temp_7d
    3. min_temp_7d
    4. rh_over_90_hours
    5. total_rainfall_7d
    6. longest_wet_period_hours

### 10. 直接使用时序数据进行预测

- **URL**：`POST /api/time_series_predict`
- **Content-Type**：`application/json`
- **请求体**：
```json
{
  "data": [22.3, 25.0, 18.1, 12.0, 4.5, 48.0]
}
```
- **说明**：
  - `data` 是长度为 6 的数组，按顺序包含：
    1. avg_temp_7d
    2. max_temp_7d
    3. min_temp_7d
    4. rh_over_90_hours
    5. total_rainfall_7d
    6. longest_wet_period_hours
  - 已有聚合特征时使用此接口
- **响应示例**：
```json
{
  "success": true,
  "prediction": 0.1234,
  "message": "预测成功"
}
```

## 三、简要对照表

| 功能           | 方法 | 路径                                     | 主要请求/响应 |
|----------------|------|------------------------------------------|----------------|
| 图片识别       | POST | /api/predict                             | file → results(最多1条) + image_result + monthly_tip |
| 病害问答       | POST | /api/ask                                 | JSON question + 可选 history → answer |
| 扣子智能体问答 | POST | /api/coze/ask                            | JSON question + 可选 history → answer |
| 识别+解读      | POST | /api/predict_with_explanation            | file → results + image_result + explanation + monthly_tip |
| 月份提示       | GET  | /api/monthly_tip                         | 无 → monthly_tip |
| 大模型状态     | GET  | /api/llm_status                          | 无 → llm_available 等 |
| 扣子智能体状态 | GET  | /api/coze_status                         | 无 → coze_available 等 |
| **地名转经纬度** | **GET** | **/api/geocode?name=地名** | 地名 → 经纬度、时区 |
| **按经纬度预测** | **POST** | **/api/time_series_predict_by_location** | 经纬度 → 发病概率 + 输入数据 |
| **直接时序预测** | **POST** | **/api/time_series_predict** | 6维聚合特征 → 发病概率 |

## 四、注意事项

- 图片格式支持：`.jpg`、`.jpeg`、`.png`、`.bmp`，单张建议不超过 10MB。
- 多轮问答时，前端需自行维护并传递 `history`，后端不保存会话。
  - 提供了根据session id查询记录的接口
- 识别接口返回的 `results` 为当前逻辑下的「最可能一条病害」，无检测时为空数组。

### 时序预测补充说明（新功能）

#### 推荐工作流程
1. **前端获取用户位置**（地名或经纬度）
2. **调用 `/api/geocode`**（若用户输入地名）→ 获取经纬度
3. **调用 `/api/time_series_predict_by_location`**（推荐）→ 获取发病概率
   - 后端自动调用 Open-Meteo 天气 API
   - 无需其他配置或密钥

#### 预测概率解读
- **0.0 ~ 0.3**：🟢 低风险 - 当前条件不利于病害发展
- **0.3 ~ 0.7**：🟡 中风险 - 需要加强监测，适当防治
- **0.7 ~ 1.0**：🔴 高风险 - 易发生晚疫病，需要立即防治措施

#### 关于 Scaler 文件
- ✅ **无需每次生成**：`scaler.pkl` 已预生成，包含在运行包中
- ✅ **永久可用**：该文件一次生成后，可以无限期使用
- ⚙️ **高级用途**：若你训练了新模型需要重新生成 scaler，请运行 `python generate_scalers.py`（此为可选）

#### 天气数据来源
- 使用 **Open-Meteo 免费 API**（无需密钥）
- 获取过去 7 天的日均温湿度与当天 24 小时逐时温度
- 自动转换为模型输入格式

#### 如有特殊需求
若需修改天气数据来源或预处理逻辑，请编辑 `backend/weather_service.py`。

如有接口变更，以后端实际返回为准；可随时通过 http://127.0.0.1:8000/docs 查看最新文档。
